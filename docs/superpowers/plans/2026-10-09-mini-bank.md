# Mini Bank API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Xây dựng API ngân hàng học tập chạy với Oracle, có chuyển tiền nguyên tử, phân quyền và chống yêu cầu lặp.

**Architecture:** Monolith, package theo nghiệp vụ. Controller nhận DTO; Service quản lý transaction; Repository truy cập Oracle. Khóa người yêu cầu trước, sau đó khóa tài khoản theo thứ tự UUID.toString() chuẩn chữ thường tăng dần.

**Tech Stack:** Java 21, Maven, Spring Boot, Spring Data JPA/Hibernate, Spring Security, Bean Validation, Oracle JDBC, Flyway Oracle, JUnit, Mockito, Testcontainers Oracle.

**Spec:** /home/quan/PersonalProject/BankingAPI/mini-bank-design.md

## Global Constraints

- Chỉ chuyển tiền nội bộ VND; không phí, không cho số dư khách hàng âm.
- Java 21; phiên bản dependency phát hành ổn định được kiểm tra tương thích và cố định ở nhiệm vụ 1.
- BigDecimal và NUMBER(19,0); tiền JSON dạng chuỗi số nguyên. Khoảng 0–9999999999999999999; chuyển tiền phải lớn hơn 0.
- Idempotency-Key 1–64 ký tự; chọn tập [A-Za-z0-9_-]. Nội dung tối đa 140 ký tự.
- HTTP Basic, BCrypt, stateless; STAFF không được chuyển thay CUSTOMER.
- Khóa APP_USER trước, BANK_ACCOUNT theo thứ tự UUID.toString() chuẩn chữ thường tăng dần; thời gian chờ khóa 5 giây cho luồng bình thường, xác minh trên Oracle.
- Ghi giao dịch, hai bút toán, idempotency và audit cùng transaction; chỉ trả thành công sau commit.
- UTC, DTO độc lập entity, ProblemDetail an toàn; không log secrets.
- Tài khoản mới có opening_balance = balance = 0; bootstrap demo riêng.
- Không dùng H2 để chứng minh khóa/rollback Oracle. Báo rõ kiểm thử bị bỏ qua.

- BANK_ACCOUNT.id và mọi FK tài khoản dùng RAW(16), Java UUID v4 sinh tại ứng dụng; API chuỗi UUID chuẩn. Account number vẫn chuỗi riêng. AUDIT_EVENT.resource_id VARCHAR2(64). Mapping Hibernate binary 16 byte xác minh bằng Oracle IT. UUID path sai định dạng trả 400.

## Review Focus

- Chuỗi tiền có dấu, khoảng trắng, số mũ, phần lẻ hoặc JSON number: từ chối 400; task 1.
- Retry thành công sau khi tài khoản bị BLOCKED: vẫn trả giao dịch cũ; task 5.
- Số dư đích tràn NUMBER(19,0): 422 và không ghi thay đổi; task 5.
- Header request ID chứa ký tự điều khiển, trang âm hoặc size quá lớn: không gây log injection/đọc không giới hạn; task 3 và 4.
- Oracle không hỗ trợ timeout hint như dự kiến: xác minh thời gian chờ bằng hai connection, chọn native WAIT 5 nếu cần; task 6.
